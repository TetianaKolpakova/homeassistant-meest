# Meest для Home Assistant

Неофіційна інтеграція для Meest ПОШТА (Україна). Версія 0.1.0.

[Публікація на GitHub](docs/PUBLISHING.md) · [Приклад картки](examples/meest-card.yaml) · [Розробка](CONTRIBUTING.md)

![Meest](custom_components/meest/brand/icon.png)

Неофіційна окрема інтеграція. Створює рівно **два постійні сенсори на акаунт**:

- **Готово до видачі** — кількість вхідних посилок зі статусом `2` і типом доставки `Branch` або `PostStation`. Атрибути `parcels` та `locations` містять списки й групи за відділеннями/поштоматами.
- **У дорозі** — вхідні посилки зі статусами `1` (відправлено), `3` (кур’єр), `7` (митниця). Список — в атрибуті `parcels`.

Нові посилки не створюють сутностей. Отримані, відхилені, повернені, архівні й вихідні відправлення не враховуються. Створені, але ще не відправлені (`0`), не зараховуються до «У дорозі». Невідомі статуси/типи залишаються в `unclassified`, а не автоматично потрапляють до лічильників.

## Встановлення

1. Розпакуйте архів. Скопіюйте папку `custom_components/meest` у папку конфігурації Home Assistant: має вийти `/config/custom_components/meest/manifest.json` (на HA OS). Не копіюйте всю зовнішню папку замість `meest`.
2. Перезапустіть Home Assistant.
3. **Налаштування → Пристрої та служби → Додати інтеграцію → Meest**.
4. Введіть той самий логін/телефон і пароль, які працювали в локальному тесті.
5. З’явиться пристрій Meest із двома сенсорами. Фактичні entity_id залежать від мови та назв у вашому HA; знайдіть їх на сторінці інтеграції.

Через налаштування інтеграції можна змінити інтервал (5–120 хвилин, стандартно 15) і ввімкнути бізнес-посилки. B2C завжди увімкнено. Після публікації репозиторій можна додати до HACS як Custom repository типу Integration. До публікації доступне ручне встановлення.

Код орієнтований на актуальний Home Assistant Core у жовтні 2026 року. Сумісність зі старими версіями не перевірялася; особливо механізми runtime_data та Retry-After у coordinator.

## Перша перевірка у вашому HA

Поки тестова посилка чекає в поштоматі, очікувано: **Готово до видачі = 1**, **У дорозі = 0**. В атрибуті `locations` має бути `type: post_station`, номер місця, адреса та посилка. Після отримання посилки вона має зникнути зі списку на наступному опитуванні. Можна викликати стандартну дію `homeassistant.update_entity` для ручного оновлення одного із сенсорів.

Сенсори використовують спільне отримання всіх сторінок. При недоступності API, неповній пагінації чи помилці формату обидва стають недоступними, замість показувати неправдивий нуль. Відхилена сесія запускає стандартну пропозицію повторного входу. Налаштування й пароль у `configuration.yaml` не потрібні.

## Авторизація та дані

Пароль використовується тільки під час входу й не зберігається інтеграцією. Access/refresh-токени зберігаються в config entry Home Assistant і можуть потрапляти до його резервних копій. Refresh ротованих токенів зберігається перед подальшими запитами; перезапуск використовує збережену сесію. Помилка авторизації запускає один refresh і один повтор запиту; якщо refresh відхилений, потрібен повторний вхід.

`expiresIn` обробляється як Unix-час для великих чисел або TTL для малих. Формат Unix-часу виведено зі значень локального тесту; робота після фактичного завершення токена ще не перевірена. Проактивний refresh запускається за дві хвилини до цього часу.

Атрибути сенсорів містять номери посилок, описи та адресу місця отримання, потрібні для відображення. Телефони, ПІБ та токени до атрибутів не включаються. Детальні списки виключаються з Recorder; історія числових станів залишається. Інтеграція не містить diagnostics із сирими відповідями та не записує секрети в лог. Немає оплати, створення посилок, зміни пароля чи відкривання поштомата.

## Межі перевірки

Локальним live-тестом підтверджено login, повне читання однієї вхідної посилки, `statusCode=2`, `service=PostStation`, негайний refresh обох токенів і читання після refresh. Це API мобільного застосунку Meest 1.5.0; його серверний контракт може змінитися.

Гілка `Branch`, статуси в дорозі, переходи після видачі, кілька заповнених сторінок і refresh після завершення access token ще потребують live-перевірки. В автоматичних тестах ці сценарії перевіряються на штучних відповідях, що не замінює серверної перевірки.

Код API та агрегації перевірено автоматично. Користувач підтвердив успішне додавання у Home Assistant через UI: сенсори показали 1 готову посилку і 0 у дорозі. В атрибутах підтверджено тип PostStation, номер місця отримання, адресу та опис посилки. Конкретні значення не публікуються. Recorder, reauth, робота після завершення токена та інші версії HA ще не перевірені наживо. Це перша тестова версія.

## Розробка

Структура `custom_components/meest` самодостатня; зовнішні API-бібліотеки не потрібні, використовується aiohttp із Home Assistant. Тести API/агрегації:

```sh
python -m unittest discover -s tests -v
```

Для запуску цих тестів поза HA потрібен aiohttp. Тести не підключаються до Meest і використовують вигадані дані. Інтеграція використовує ConfigEntry.runtime_data, DataUpdateCoordinator та стандартний reauth. Архітектура звірена з [документацією HA щодо опитування](https://developers.home-assistant.io/docs/integration_fetching_data/) і [config flow](https://developers.home-assistant.io/docs/core/integration/config_flow/).
